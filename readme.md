1. Контекст и цели

Текущий интерфейс игры выполнен в тёмной стилистике с использованием Modular Game UI Kit, но:

· Не хватает глубины и «воздушности» (элементы выглядят плоскими).
· Отсутствует адаптивность для разных устройств.
· Нет анимаций и обратной связи на действия пользователя.
· Информация часто передаётся текстом, а не визуально.

Цель — превратить UI в современный, «стеклянный» (Glassmorphism), адаптивный и анимированный интерфейс, который соответствует трендам 2026 года и улучшает восприятие игры.

Главные задачи:

· Использовать полупрозрачные панели с размытием (backdrop-blur) для создания глубины.
· Сделать вёрстку Mobile-First — адаптировать под любые экраны.
· Внедрить плавные анимации и микровзаимодействия.
· Улучшить визуальную иерархию через цвет, размер и прогресс-бары.
· Упростить навигацию и группировку элементов.

2. Ключевые принципы дизайна

1. Glassmorphism (стекло)
   · Панели: backdrop-blur-md, bg-white/5, border border-white/10, тень 0 8px 32px rgba(0,0,0,0.3).
   · Интенсивность размытия регулируется в зависимости от контекста (модалки сильнее, карточки слабее).
2. Mobile-First
   · Все компоненты проектируются сначала для мобильных устройств, затем адаптируются для десктопа (sm:, md:, lg:).
   · Минимальный размер интерактивных элементов — 44px (для удобства пальцев).
3. Анимация и отклик
   · Использовать framer-motion для плавных переходов между состояниями, пульсации активных элементов, появления карточек с задержкой.
   · Отклик на нажатие (scale, изменение цвета) — мгновенный.
4. Иерархия через цвет
   · Индиго (--primary) — основной акцент.
   · Зелёный — опыт, синий — мана, красный — здоровье, жёлтый — золото.
   · Статы и прогрессы должны читаться без текста.
5. Минимализм
   · Убирать лишний текст, использовать иконки и числовые индикаторы.
   · Карточки должны содержать только ключевую информацию, детали — в модалках или при клике.

4. Этап 1: Базовые компоненты (2–3 дня)

Создать переиспользуемые UI-компоненты в папке src/components/ui/.

4.1. GlassPanel

· Пропсы: intensity?: 'light' | 'medium' | 'heavy', className, children.
· Реализация:
  ```tsx
  <div className={cn(
    'backdrop-blur-md border border-white/10 rounded-2xl shadow-glass',
    intensity === 'light' && 'bg-white/5',
    intensity === 'medium' && 'bg-white/10',
    intensity === 'heavy' && 'bg-white/15',
    className
  )}>
    {children}
  </div>
  ```
· Использовать для модальных окон, карточек, боковых панелей.

4.2. GlassCard

· Карточка с заголовком, иконкой, описанием и действиями.
· Структура: GlassPanel внутри, с отступами и гибкой вёрсткой.
· Адаптивность: на мобиле — полная ширина, на десктопе — сетка.

4.3. ProgressBar

· Компонент с анимированным заполнением.
· Пропсы: value, max, color (по умолчанию --primary).
· Использовать framer-motion для плавного изменения ширины:
  ```tsx
  <motion.div 
    className="h-full rounded-full" 
    style={{ backgroundColor: color }}
    initial={{ width: 0 }}
    animate={{ width: `${(value / max) * 100}%` }}
    transition={{ duration: 0.6, ease: "easeOut" }}
  />
  ```

4.4. TabBar и TabPanel

· Для переключения между разделами (статы, экипировка, навыки и т.д.).
· Использовать useState для активной вкладки.
· Анимация смены контента — fade.

4.5. Modal (на основе Radix Dialog)

· Улучшить существующие модалки: добавить стеклянный фон, плавное появление, закрытие по клику вне.
· Использовать GlassPanel внутри.

4.6. Button (переработанный)

· Варианты: primary (индиго-градиент), secondary (стеклянный), destructive (красный).
· Добавить анимацию нажатия (scale-95).

Результат: Библиотека базовых компонентов готова к использованию во всех страницах.

5. Этап 2: Dashboard (главный экран) (3–4 дня)

Переработать src/pages/DashboardPage.tsx.

5.1. Верхняя панель (профиль)

· Заменить статичный заголовок на GlassPanel с аватаром, именем, уровнем и прогрессом до следующего уровня.
· Добавить кнопку «Редактировать» (иконка карандаша).
· Отображать валюты (золото, гемы) в виде маленьких иконок с числом справа.

5.2. Статистика (плитки)

· Вместо двух отдельных блоков (Combat Level и Play Time) сделать три плитки: уровень, время игры, количество побед.

· Адаптивность: на мобиле — одна колонка, на десктопе — три в ряд.

5.3. Список навыков

· Группировать навыки (Combat, Gathering, Artisan) как отдельные секции.
· Каждый навык — горизонтальная карточка с иконкой, названием и прогресс-баром уровня.
· Активный навык подсвечивается индиго-обводкой и лёгкой пульсацией.
· Использовать сетку: на мобиле — 2 колонки, на десктопе — 4.

5.4. Квесты / Daily

· Отображать два ближайших активных квеста в виде карточек с прогрессом и наградой.
· Кнопка «Все квесты» ведёт на страницу QuestsPage.

5.5. Навигационные кнопки (Town, Quests, World, Pets, Bosses)

· Заменить текстовые кнопки на иконки с подписями в виде карточек с эффектом стекла.
· Сделать их адаптивными: на мобиле — сетка 2×3, на десктопе — горизонтальный список.

Результат: Главный экран стал «живым», информативным и приятным глазу.

12. Технические рекомендации

· Стек: React, TypeScript, Tailwind, Framer Motion, Radix UI.
· Структура:
  · src/components/ui/ — базовые компоненты.
  · src/components/glass/ — стеклянные обёртки.
  · src/pages/ — страницы (каждая будет переработана).
  · src/hooks/ — хуки для анимаций и адаптивности (например, useMediaQuery).
· Адаптивность: использовать Tailwind-классы sm:, md:, lg:, xl:. Для сложных случаев — useMediaQuery из react-responsive или кастомный хук.
· Управление состоянием: Zustand для UI-состояний (открытые модалки, активные табы).
· Производительность: избегать backdrop-blur на больших областях, использовать will-change: transform для анимированных элементов.
